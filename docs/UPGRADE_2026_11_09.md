# NexEase workflow and Android update

This branch targets the current main commit `e240d60` and keeps the live Singapore deployment unchanged until merged.

## Requested behavior

| Request | Implementation |
| --- | --- |
| Workforce navbar | Dashboard plus employees, sites, assignments, attendance, timesheets, leave, advances, monthly inputs, pay runs, payslips, billing, accounts, reports and settings. Existing role/module checks remain. |
| Quick-invoice quantity | Goods are deducted when the quick draft is saved. Five units from zero show -5. A selected warehouse is used; otherwise the oldest active warehouse is used. A tenant with no warehouses gets a Quick billing warehouse. Service lines do not affect stock. Cancelling returns the quantity; issuing does not deduct it again. |
| Reorder alerts | Products has a Reorder control. Save a per-product level, with total physical stock summed across warehouses. The bell generates an alert when stock is below the level, once per low-stock episode per user. Stock recovering to the level resets the episode. Bell polling detects changes. Products also shows stock quantity, including negative values, for inventory readers. |
| Email verification | Settings → My email sends a single-use, 24-hour verification link. Verified-only sharing uses the configured NexEase/system From address and the verified user in Reply-To. It does not impersonate a mailbox. Existing authenticated SMTP mailboxes continue sending directly from their own addresses. System outgoing email must be configured on the backend and worker. |
| Payslips and details | Approved payslips open as PDF pop-ups with download/share and PDF print controls. Draft payroll details open in a dialog. Employees now have an Email field. Select employees for separate queued emails, a selected PDF ZIP, or guided individual WhatsApp sharing. Each email contains only that employee's PDF. |
| AI | A saved entry closes the assistant and displays the global success dialog. Errors and unresolved entries remain open. |
| Admin invoice edit | Administrators can amend line quantities/prices/tax/discounts/descriptions, add/remove products, edit billing name/address, due date and notes. Issued amount changes create a balanced delta journal and preserve applied payments. A posted original invoice journal is required. A changed/stale invoice is rejected. |
| Document logs | Compact access/delivery tabs, summary counts, document/action/recipient/status filters, clear/refresh, empty/error states and detail pop-ups. Access serialization tolerates a deleted user reference. Server audit permission remains mandatory. |
| Create menu | Menu labels use the menu text colour instead of inheriting white header text. |
| Android refresh | Pull down at the top of the main workspace to refresh active data queries. Does not reload the WebView or discard forms; disabled over forms, inputs and open dialogs. |
| Android icon | Existing NexEase vector mark with transparent background for adaptive and legacy launcher resources. Android launchers still control their icon mask and themed appearance. |

## Boundaries

- Verify an address to receive replies there. Sending directly FROM Gmail/Microsoft/Yahoo still needs authenticated mailbox/provider authorization; verifying a link alone cannot grant it.
- WhatsApp bulk selection is a guided queue. The user reviews each recipient and attaches/shares the employee's PDF. Automatic server-side WhatsApp delivery requires a separately configured WhatsApp Business provider and is not included.
- An invoice's customer master reference is preserved. Issued invoice dates remain tied to their original accounting period. Sales-order product/quantity changes must follow fulfillment correction. Submitted IRP/e-way documents and invoices with live credit notes require their correction workflows first.
- Historic quick invoices are not retrospectively deducted. Review old stock differences before making manual adjustments.
- The existing Mongo application uses compensating writes and scoped locks, not multi-document database transactions. Ordinary failures are compensated and tested. A process killed mid-amendment still requires accounting/stock review; do not clear a stale lock without reviewing the affected invoice and movements.
- SMTP is not an exactly-once transport. Delivery receipts prevent normal duplicate retries; a worker crash after provider acceptance and before the receipt can still require checking delivery before retrying.
- An Android SDK is not present in the implementation environment. Android web export is tested; the actual APK and device gestures/launcher behavior need the local Android build and a device check.

## Deploy and check

1. Review/merge the PR. Wait for Singapore backend, frontend and worker to finish deploying the same commit. The worker must recognize the new `PAYSLIP_EMAIL` job type before queueing payslips.
2. No relational migrations are required. Mongo collections for verified senders and reorder settings are created on first use.
3. Test a new goods quick invoice in a test organization; check Products/Inventory and cancellation reversal.
4. Save a reorder level above the current quantity and refresh the notification bell. Restock and cross the level again to check the next alert.
5. Verify the sender using the real inbox. Share a document to a test recipient and confirm From/Reply-To. SMTP credentials stay in Render; do not add them to the repository.
6. Save employee email/phone details. Use approved payroll to test preview, a selected ZIP, one email and the WhatsApp sharing queue.
7. Test an admin invoice increase/decrease and inspect the delta journal and balance. Do not test financial edits on an IRP-submitted invoice.

## Windows APK build

After pulling this branch/merged main into the active repository:

```powershell
Set-Location 'E:\NexEase-Git-20261105-004821'
powershell -ExecutionPolicy Bypass -File .\frontend\scripts\build-singapore-apk.ps1
```

Requires JDK 21+, Node dependencies and Android SDK. The debug APK is written to `Downloads\NexEase-Singapore.apk`. Existing installed apps may retain a saved backend override: use `https://nexease-backend-singapore.onrender.com/api/v1`. Preserve your existing signing setup when distributing release updates.
